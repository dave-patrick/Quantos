# Design: Google Tasks two-way sync (draft 5, 2026-10-30)

Draft 2 answered the draft-1 critic (33 gaps) and readiness (28 questions) passes; draft 3 the draft-2 passes (15 and 15); draft 4 the draft-3 passes (11 and 6); draft 5 the draft-4 passes (7 and 7), after the owner allowed one revision beyond the 3-revision cap; draft 6 the draft-5 passes (5 and 2), after the owner allowed one more.

## Why
The owner wants Google Tasks as an optional counterpart to Quantos tasks (phone widgets, Gmail side panel).
Quantos Markdown task nodes stay the source of truth. Not on the BUILD-PLAN roadmap; the owner's answers in the
2026-10-30 session (two-way sync, desktop + Android, owner registers the Google Cloud project, single user) are the scope decision.

## Decisions to flag to the owner
**Approved by the owner on 2026-11-02: D1–D8 and the Android loopback and delete-guard choices below, as written (Quantos wins on conflicts).**

- D1. **Conflicts: local wins** (not "newer timestamp wins"). If the same field changed on both sides since the last sync, the Quantos value is written to Google.
  Reason: local `modified` is bumped by unrelated writes (reminders, rollover, my_day, `gtask_*` writes), has second resolution and is not touched by outside editors, so it cannot be compared with Google's `updated`.
- D2. **`cancelled` is pushed to Google as completed**; a Google "completed" never turns a cancelled task into done.
- D3. **Notes over 8,000 characters** are not synced (either way) for that task; title, due, done state and parent still sync.
- D4. Android sync is **foreground-only**; no foreground service is added.
- D5. **One syncing device is the supported setup.** A second device on the same shared vault attaches to existing links through the `gtask_id` hints and works, but while a hint is still travelling through shared-vault sync the second device can import a copy of a task the first device just pushed.
  That duplicate is repaired automatically (see "Duplicate hints"), but the user guide recommends enabling Google Tasks on one device.
- D6. A Google-side rename goes through `WriteService.Rename`, so it rewrites `[[old title]]` links in other notes exactly as renaming in Quantos does. Accepted, and tested.
- D7. Preview and confirmation are **per mapping**; the import cutoff is fixed at 30 days before the preview (no UI to change it in v1).
- D8. **Wiki-links in notes are lossy through Google.** Links are converted to their display text when pushed (so raw ids never appear in Google), and a notes edit made on Google replaces the local body, turning links in it into plain text. Mapping the same workspace to different lists on two devices sharing a vault is unsupported.

## Scope in
- Opt-in, one Google account, per device. Off until connected. Nothing contacts Google before that.
- Each mapping pairs one Quantos workspace with one Google list. Validation (HTTP 400 on `PUT /settings`): a workspace appears in at most one mapping and a list in at most one mapping.
- Two-way sync of five fields: title, notes (body), due date (date only), done/open state, parent (one level).
- Deletes both ways with a guard; a preview with counts before the first sync.

## Scope out
- Recurring tasks (any task with `recurrence` or `series`), `depends_on`, priority, effort, `planned`, reminders, time blocks, sprint, project, assignees, supertags, `time_spent`, archive state, sibling order:
  never sent to Google and never overwritten by a pull.
- Due times, Google recurrence, multiple accounts, multi-user, push notifications, Calendar/Gmail, cross-list moves (a task whose workspace changes is suspended, below),
  Google tasks assigned from Docs/Chat (`assignmentInfo` present): skipped and counted.

## Key decision: in-process, not a worker
`src/Quantos.FolderBridge` is a separate process; Android cannot run one. The engine lives in `Quantos.Core`; a `BackgroundService` in the Backend runs it like
`Hosting/SyncCoordinator.cs`. `android/Backend/Quantos.Android.Backend.csproj` compiles `src/Quantos.Backend/**/*.cs` by glob, so new Backend files are included on Android automatically.
Plain `HttpClient` + `System.Text.Json`; no `Google.Apis.*` packages.

## Auth (bring your own Google Cloud client)
Owner setup (also written into the user guide): create an OAuth client of type **Desktop app**; enable the Google Tasks API; set the consent screen to **In production** (unverified, so a warning screen
appears and the app is capped at 100 users; in "Testing" Google expires refresh tokens after 7 days); scope `https://www.googleapis.com/auth/tasks` (sensitive scope). The token request needs the client secret, which for Desktop clients is not secret in Google's sense.
Google also ends a refresh token after 6 months unused or on password change/revoke; both surface as `NeedsReconnect`.

Storage: client ID in config; client secret and refresh token sealed with `AiSettingsStore.KeyProtector`. If `Unprotect` returns null or throws (restored device, reinstall) the state is `NeedsReconnect` and the person re-enters the secret.

Flow (`GoogleOAuth.cs`):
1. `POST /api/google-tasks/connect` creates one in-memory pending flow in the coordinator: `{State(32 random bytes, base64url), Verifier(PKCE, 64 random bytes), RedirectUri = http://127.0.0.1:{ServerAddress.Port}/oauth/google/callback, Expires = now+10 min}`.
   A new Connect, Disconnect, or process restart discards it (the person clicks Connect again). It returns `{authUrl}`:
   `https://accounts.google.com/o/oauth2/v2/auth?response_type=code&client_id=…&redirect_uri=…&scope=…tasks&state=…&code_challenge=…&code_challenge_method=S256&access_type=offline&prompt=consent`.
2. In a native client (`isNativeClient` in `frontend/src/lib/platform.ts`) the page opens `authUrl` with `bridge.send({type:'open-external', url: authUrl})`. Windows already handles `open-external` (`MainForm.cs:390`, `OpenExternal`, unchanged).
   **Android needs a new `case "open-external"` in `MainActivity.NativeMessage` (`android/MainActivity.cs`, the switch starting at line 155)**; message shape `{type:"open-external", url:string}`; it starts `Intent.ActionView` only if `GoogleOAuth.IsConsentUrl(url)` is true
   (Core, unit-tested: scheme `https`, host exactly `accounts.google.com`, path `/o/oauth2/v2/auth`, no user-info). (The existing `ActionView` at line 444 is gesture-gated and would silently drop an asynchronously opened URL.)
   In an ordinary browser (backend opened with `--open`, where `bridge.send` does nothing) the page instead shows a "Continue to Google" link (`<a href={authUrl} target="_blank" rel="noopener noreferrer">`) that the person clicks; the callback works in that case because the browser can reach 127.0.0.1.
3. `GET /oauth/google/callback?code&state` (root, not under `/api`). It is handled **inside `RequestSecurity.InvokeAsync`, immediately after the Host check (lines 22-27) and before the Origin and Sec-Fetch-Site checks (lines 29-40)**, because the redirect from Google is `Sec-Fetch-Site: cross-site`.
   A static helper `GoogleOAuthCallback.TryHandleAsync(HttpContext ctx)` (Backend `Hosting/`) is called there; it matches only `request.Path.Value == "/oauth/google/callback"` (exact, case-sensitive) and returns `false` for every other path, so every other route keeps the Origin and Sec-Fetch-Site checks. It resolves `GoogleTasksCoordinator` from `ctx.RequestServices`, writes the whole response and returns `true`; `InvokeAsync` then returns without calling `next`, so the static-file/SPA handler is never reached. Program.cs registers services only; it does not map this route.
   Any method other than GET → 405. It does not need the `/api` token check, because it is not under `/api`. It accepts the request only if a pending flow exists, is unexpired, and `state` equals the flow's (constant-time compare); the flow is consumed (single use) on the first hit with the matching `state`, or when it has expired; a request with a wrong `state` gets HTTP 400 and does **not** consume or cancel the flow (so a stray cross-site GET cannot cancel the person's real sign-in).
   The handler exchanges the code (`POST https://oauth2.googleapis.com/token`, `grant_type=authorization_code`, `code_verifier`, `redirect_uri`, `client_id`, `client_secret`). If the token response `scope` does not contain `https://www.googleapis.com/auth/tasks` (Google's consent screen lets the person untick it), nothing is stored and the page and status say "Tick the Google Tasks box on the consent screen and try again".
   Otherwise it stores the refresh token sealed and responds with a static HTML page ("You can close this tab") with headers `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`, no cookies.
   `code`/`state` must not appear in logs (test below). Failure after a matching state (token exchange error or missing scope) → HTTP 400 static page, flow consumed; wrong state → HTTP 400, flow kept.
4. Access tokens are cached in memory until `expires_in - 60 s`. On a 401 the client refreshes once and retries once. `invalid_grant` (or a second 401) → `GoogleAuthException` → `NeedsReconnect`; sync stops, no task data is touched.
5. Disconnect: `POST https://oauth2.googleapis.com/revoke?token=…` (failure/offline is ignored and the UI says "Quantos couldn't tell Google; remove access at myaccount.google.com/permissions"), then config and state are deleted.

**Android risks and the first implementation step (spike, on the physical SM-S948U):** Android has no `OnResume` today (`MainActivity.cs:277-293` has only `OnPause`/`OnDestroy`) and the process may be frozen or killed while Chrome is foreground.
Spike pass = three of three runs where Quantos is backgrounded in Chrome for the consent (one run waits 60 s on the consent screen) and the redirect reaches Kestrel and the token exchange succeeds. Fail = redirect error from Google, browser cannot reach 127.0.0.1, or the process is dead on return.
Spike code: a temporary `POST /api/google-tasks/spike` Backend endpoint (User actor only) that uses the Client ID and secret already saved through `PUT /settings`, runs the Connect flow above, and a temporary "Test Google sign-in" button in the new Settings section that shows the endpoint's `{ok, stage, error}` (`stage` = `opened`, `callback`, `token`). The owner holds the phone; the assistant runs the three runs and records the outcome in `HANDOVER.md`. The spike endpoint is removed (or promoted into the real `/connect` flow) before step 2 ends; steps 2 and 3 (pure Core) do not depend on the result. If the spike fails, stop and bring plan B (Android-type client + custom-scheme intent) back to the owner.
Decision D4 resolves the earlier "if a resume hook exists": add `protected override void OnResume()` to `MainActivity` that gets the coordinator with `app.Services.GetRequiredService<GoogleTasksCoordinator>()` (the same way `MainActivity.cs:45` gets `ServerAddress`) and calls its instance method `Kick()` (an immediate non-blocking sync request); there is no other background sync on Android.

## Config, state and types
Config `Paths.Settings/google-tasks.json` (`QuantosPaths.Settings` is `ClientData/settings`), class `GoogleTasksSettingsStore(string settingsFolder)` with the same shape as `AiSettingsStore` (lock, `AtomicFile`, `JsonSerializerDefaults.Web`; missing or corrupt file = default = Off):
```
record GoogleListMapping(string Workspace, string ListId, string ListTitle, DateTimeOffset? ImportCutoff, bool Confirmed);
record GoogleTasksConfig {
  string? ClientId; string? ProtectedClientSecret; string? ProtectedRefreshToken;
  int IntervalSeconds = 120 /*30..900*/; string? Vault /*vault root, pinned*/;
  List<GoogleListMapping> Mappings = []; }
```
`Vault` is pinned by the first `PUT /settings` that saves anything while it is null, and cleared by `DELETE /`. Off = no refresh token. `lastSynced`, `nextAttempt`, `progress` and the per-cycle `counts` are held in memory only (lost on restart); `counts.linked` is computed from `state.json`.
`PUT /settings` semantics: an omitted or empty `clientSecret` keeps the saved one; a non-empty one replaces it; changing `clientId` or `clientSecret` deletes the refresh token (state becomes Off, press Connect again). Each mapping's `Workspace` must exist in the vault (the list the workspace switcher uses) and `IntervalSeconds` outside 30..900 is rejected with 400, not clamped.
`mappings` in `PUT /settings`: omitted = keep the saved mappings; `[]` = remove all (with the mapping-change cleanup below). The request carries no `confirmed`/`importCutoff`: a request mapping matches a saved one by identity `(workspace, listId)` and keeps its `Confirmed`/`ImportCutoff`; any other pair is a new mapping with `Confirmed=false`.
A mapping's `Confirmed`/`ImportCutoff` belong to that mapping; changing a mapping's workspace or list creates a new mapping identity with `Confirmed=false`, and the other mappings are unaffected. A mapping whose workspace was renamed or removed is `Paused` with reason "Workspace missing: <name>".
State `ClientData/google-tasks/{vaultKey}/state.json`, `vaultKey` = first 16 hex chars of SHA-256 of the lower-cased full vault root; written with `AtomicFile`; `version: 1`:
```
{ version, Cursors:{ listId: "RFC3339 max updated applied" },
  Links:{ taskId(ULID): { Gid, ListId, GoogleUpdated, Missing /*int, persisted; consecutive completed cycles in which the task was missing without a trash entry*/, Base:{
      Title:{L,G}   /* normalised title strings last seen on each side */,
      Notes:{L,G}   /* SHA-256 hex of the normalised notes text last seen on each side */,
      Due:{L,G}     /* yyyy-MM-dd or null */, Done:{L,G} /* bool */,
      Parent:{L,G}  /* L = parent task id (Props.LinkId of the stored value) or null; G = parent gid or null; compared across sides by mapping gid ↔ task id through Links */ } } },
  Intents:[{ TaskId, ListId, CursorAtIntent /* the list's cursor (a Google `Updated` value) when the insert began */, TitleNorm, Due }]  /* push-inserts in flight */,
  PendingDeletes:[{ TaskId, Gid, ListId, Title, Direction: "toGoogle"|"toQuantos" }] }  /* persisted; keyed by TaskId */
```
Initial `Base` for a link created without a write (hint relink, second-device attach, state rebuild): `Base.L` and `Base.G` are seeded from the current normalised values of each side; for any field where the two sides differ, local wins (the Google value is overwritten on this cycle, `Conflicts++`); where they are equal, only the seed is stored. No deletes are issued for a link in the cycle in which it was created.
Status ↔ done matrix: `Done.L` = `status` is `done` or `cancelled` (true) vs `todo`, `doing`, `waiting` (false); `Done.G` = Google `status == completed`. Push: `Done.L` true → `completed`, false → `needsAction` (D2). Pull of `completed` onto an open task → `status: done`; pull of `needsAction` onto a `done` **or `cancelled`** task → `status: todo` (a Google reopen replaces `cancelled`); onto `doing`/`waiting` → no change.
Title length: `Base.Title.L` stores the full normalised local title and `Base.Title.G` the normalised title as Google last returned it (so truncated). A local title change is `L != Base.L`; a Google change is `G != Base.G`. The pushed value is `truncate(L, 1024)`, and "sides already equal" means `truncate(L, 1024) == G`, so a long title does not look changed on the next cycle.
Base keeps what each side last had (L = local, G = Google) so a change is "this side differs from its own last-seen value". That makes the merge independent of clocks and of lossy round trips (for example `[[links]]` rewritten by `ResolveLinks`).
State lost or corrupt: links are rebuilt from the `gtask_id`/`gtask_list` hints (task still exists on Google); with no `Base`, any field that differs resolves local-wins, and no deletes are issued for that cycle.

Vault frontmatter on a linked task: `gtask_id`, `gtask_list`. Written in the same write that creates the link (pull: inside `Create`; push: one `UpdateFields` right after `Insert`). Etags and timestamps are never in the vault.

Api (`IGoogleTasksApi`, DTOs):
```
record GTaskList(string Id, string Title);
record GTask(string Id, string Title, string? Notes, string? Due /*UTC date yyyy-MM-dd*/, bool Completed, string? CompletedAt,
             string? Parent, string Updated, string? Etag, bool Deleted, bool Hidden, bool Assigned);
record GTaskPage(IReadOnlyList<GTask> Items, string? NextPageToken);
record GTaskWrite { Optional<string> Title; Optional<string?> Notes; Optional<string?> Due; Optional<bool> Completed; }  // Optional distinguishes absent from explicit JSON null
Task<IReadOnlyList<GTaskList>> ListTaskLists(ct);   Task<GTaskList> CreateTaskList(string title, ct);
Task<GTaskPage> ListTasks(string listId, DateTimeOffset? updatedMin, string? pageToken, ct); // always showCompleted=showDeleted=showHidden=showAssigned=true, maxResults=100
Task<GTask?> Get(string listId, string id, ct);                         // GET …/tasks/{id}; null on 404/410; a returned task with Deleted=true is treated as absent
Task<GTask> Insert(string listId, GTaskWrite w, string? parent, ct);   // POST …/tasks?parent=
Task<GTask> Patch(string listId, string id, GTaskWrite w, ct);          // PATCH …/tasks/{id}
Task<GTask> Move(string listId, string id, string? parent, ct);         // POST …/tasks/{id}/move?parent= (omit parent = top level; no `previous`)
Task Delete(string listId, string id, ct);                              // 404 and 410 are success
class GoogleApiException(int Status, string? Reason, TimeSpan? RetryAfter) : Exception;
class GoogleAuthException : Exception;                                  // invalid_grant, or 401 after one refresh
```
Wire rules: `due` is `YYYY-MM-DDT00:00:00.000Z`; read it as the UTC date part, never converted to local time. Title max 1,024 characters (truncate on push), notes max 8,192 (we cap at 8,000, D3).
Clearing sends JSON `null` (`"due":null`, `"notes":null`). Reopening sends `{"status":"needsAction","completed":null}`; completing sends `{"status":"completed"}`. Optimistic concurrency (`If-Match`) is NOT used (support unverified): correctness comes from the Base comparison; the returned `etag`/`updated` are stored only for echo suppression.

Every Google call uses one `HttpClient` with a 30 s timeout; a timeout is reported as "Google did not respond in time" and counts as a failure for back-off; it never holds the gate beyond cancellation.
Engine: `Task<GoogleSyncReport> Run(CancellationToken ct)` and `Task<GoogleSyncPreview> Preview(string workspace, CancellationToken ct)`. Preview performs reads only (no local writes, no Google mutations, no state writes) and returns
`record GoogleSyncPreview(DateTimeOffset Cutoff, int CreateInGoogle, int ImportToQuantos, int Link, int Excluded)`, all counts. `Cutoff` = now − 30 days (D7). With E = the mapping's eligible local tasks (step 3 rules, cutoff applied) and G = its non-deleted, non-assigned Google tasks that pass the cutoff:
- `Link` = tasks in E that already have a state link, or whose `gtask_id`/`gtask_list` hint matches a task in G (these will be relinked, not duplicated);
- `CreateInGoogle` = tasks in E with no link or matching hint;
- `ImportToQuantos` = tasks in G not matched by any link or hint;
- `Excluded` = local tasks in the mapped workspace that are not in E (archived, recurring/series, `ReadOnly`, outside the closed-task cutoff, hint for another list) plus Google tasks that are assigned or completed before the cutoff. (`Excluded` is not the report's `Skipped`, which counts per-cycle intentional non-syncs such as locked, over-cap and suspended tasks.)
`Run` processes only mappings with `Confirmed = true`.
`record GoogleSyncReport(int Pushed, int Pulled, int Deleted, int Linked, int Skipped, int Conflicts, int PendingDeletes)`. `Skipped` = items intentionally not synced this cycle (locked, over the notes cap, assigned, suspended, over-depth); `PendingDeletes` = paused deletions awaiting the person; `Conflicts` = same-field both-sides changes resolved local-wins.
The engine writes with `private static readonly Actor GoogleActor = new(ActorKind.System, "google-tasks")`.
Test seams (constructor injection, no statics): `GoogleOAuth(HttpClient http, Uri? authBase = null, Uri? tokenBase = null, Uri? revokeBase = null)` (defaults are the Google URLs) holds the pending flow and exchanges/refreshes/revokes tokens; `GoogleTasksApi(HttpClient http, IGoogleAccessTokens tokens, Uri? baseUri = null)` (default `https://tasks.googleapis.com/tasks/v1/`); `interface IGoogleTasksApiFactory { IGoogleTasksApi Create(); void Forget(); }` (production: builds `GoogleTasksApi` using `GoogleOAuth` for tokens); `GoogleTasksSyncEngine(WriteService writes, TaskService tasks, Clock clock, IGoogleTasksStateStore state, IGoogleTasksApi api)`;
`GoogleTasksCoordinator(VaultHost host, GoogleOAuth oauth, IGoogleTasksApiFactory apis, GoogleTasksSettingsStore settings)` is registered in DI, so tests construct it directly with fakes. For the middleware callback test, `Program.Build` gains an optional `Action<IServiceCollection>? configureServices` parameter that tests use to replace `GoogleOAuth` and `IGoogleTasksApiFactory` (same hosting approach as `tests/Quantos.Tests/CredentialSecurityTests.cs`).

A filter like `SyncEndpoints.cs:14-17` rejects every method, GET included, unless `Actor().Kind is ActorKind.User` (403 "Only you can configure Google Tasks sync."). Errors use `QuantosException` with 400 (validation), 409 (not ready), 503 (offline).

Status: top-level `state` is `Off` (no refresh token), `NeedsReconnect` (auth failure, missing scope or unsealable secret), `Paused` only for global reasons ("Open the vault this was set up for"), otherwise `Connected`.
Per-mapping `state:"Paused"` reasons: "Review the preview first" (unconfirmed), "List missing: <title>", "Workspace missing: <name>"; other mappings keep syncing. Pending deletions never pause anything: they only hold the deletions themselves. Held entries are persisted in `state.json`, keyed by task id, and stay until Apply or Cancel (the cursor may advance while entries are held; each entry carries its gid, so a Google-side deletion seen only once is not lost). Each cycle merges newly detected deletions into the held set (an entry whose task has reappeared or whose condition no longer holds is dropped) and reports it in `pendingDeletes`.

## Sync cycle
`Run` loops mappings; per mapping (each list with its workspace):
1. **Fetch**: `ListTasks(listId, updatedMin = cursor − 1 min, pageToken…)` until no `NextPageToken` (first run: no `updatedMin`). Apply only after all pages are fetched. The cursor is advanced to the max `Updated` seen only if the whole mapping finished without a fatal error; a cancel or fatal failure leaves it unchanged (re-fetch is idempotent because of Base). A mapping whose cursor was reset during this pass (keep-if-edited and Cancel rules below) is excluded from the advance: its cursor stays null and the next cycle does a full fetch.
2. **Local snapshot**: `TaskService.List(workspace, includeClosed:true, includeArchived:true)` gives the metadata used for eligibility and mapping (`TaskDto`: `Id`, `Title`, `Workspace`, `Status`, `Due`, `Parent`, `Completed`, `Recurrence`, `Series`, `Archived`, `Created`, `Modified`). `TaskDto` has no hints, lock state, body or hash, so for every eligible or linked task the engine reads the node once with `WriteService.Get(id)` (a `Node`: `Properties["gtask_id"]`, `Properties["gtask_list"]`, `Locked`, `ReadOnly`, `Body`, `Hash`). Cost: one file read per such task per cycle (hundreds is fine). **Write protocol for one task in one cycle** (an `UpdateFields` or `Rename` changes the file and therefore its hash, so a hash may be used only once): all changed local fields (body, due, status/completed, parent) are coalesced into **one** `UpdateFields(id, node.Hash, set, remove, GoogleActor, body)` call using the hash from the freshest read; then, if the title changed, the engine re-reads the node (`WriteService.Get`) and calls `Rename`; then re-reads once more to compute Base. The hint write after a push-insert is its own call, using a re-read hash.
   **Local snapshots for trash checks**: once per cycle, inside `WriteService.Exclusive`, the engine calls `TrashStore.List()` a single time and keeps the entry ids in a `HashSet` (`FindById` scans every manifest from disk, so it is never called per task).
3. **Eligible (local)**: `type: task`, in the mapped workspace, not archived, not `Node.ReadOnly` (a YAML error or newer schema cannot record a link, so such tasks are `Skipped` and never pushed), no `recurrence` and no `series`, and not (closed with `completed` (fallback `modified`) older than the mapping's `ImportCutoff` and unlinked).
   **Hint list rule**: if the task carries `gtask_list` and that list is mapped on this device, it belongs to that mapping; if the list is not mapped on this device but the task's workspace **is** mapped (an old mapping, or the mapping was changed), the hint is stale: `gtask_id`/`gtask_list` are removed and the task is treated as unlinked (it is pushed to the workspace's current list; the Google task in the old list is left untouched); if neither the list nor the workspace is mapped here, the task is outside this device's sync and untouched (`Skipped`). Mapping the same workspace to different lists on two devices sharing a vault is unsupported (the hints would flip between them).
   **Suspended**: a linked task that becomes ineligible (archived, gains recurrence/series, moved to another workspace) keeps its link but is skipped for pushes and pulls (counted in `Skipped`); the Google task is left alone, never deleted. Eligible again → resumes. No cross-list moves.
   **Locked** (`Node.Locked`, not `ReadOnly`): never edited, renamed, completed, re-parented or trashed by the engine because of Google changes (`Skipped`); it can still be pushed to Google, and its `gtask_id`/`gtask_list` hint writes and removals use `UpdateFields(..., derived: true)` (the existing flag that skips `LockRefusal`) because they are sync metadata, never content. The engine checks `Locked`/`ReadOnly` itself because `Rename` and `Trash` do not all refuse locked nodes.
4. **Link resolution** for each Google task in the fetched pages: state link by gid; else a local task whose `gtask_id` equals the gid and `gtask_list` equals the list and which no other task claims → relink, unless that Google task is `Deleted` (then the hint is stale, see below). This is how a second device attaches.
   A local task with a hint but no state link whose gid was not in the fetched pages (the fetch is incremental) is checked with `IGoogleTasksApi.Get`; if it returns null or `Deleted` the stale `gtask_id`/`gtask_list` are removed (`UpdateFields(remove:…)`) and the task is treated as unlinked (for example restored from trash). The same removal applies to the kept task in a cancelled pending delete (below).
   **Duplicate hints** (copied task, or the two-device race in D5): among local tasks in a mapped list that claim the same gid, the owner is chosen by a device-independent rule so every device picks the same one: the earliest `created`, ties broken by the smaller task id (the state link is not used). The state link is moved to the owner. If another task's normalised title, due, done state and notes equal the owner's, is not locked/read-only, and has no non-trashed subtasks (`Trash` cascades), it is a redundant copy and is trashed with `WriteService.Trash` (recoverable) and its link removed from `Links`; otherwise only its `gtask_id`/`gtask_list` are removed (`derived: true`) and it is pushed as a new task. (These are vault writes that shared-vault sync propagates; because the owner is always the older task, a device never trashes the older original, and no device then reads a trashed original as a local delete.)
   **Vanished gids**: a linked gid missing from a full fetch (no cursor) is treated as Google-deleted. A `Patch`, `Move` or `Get` that returns 404/410 for a linked task is treated the same way: the task takes the Google → Quantos delete path below (with its guard and its keep-if-edited rule).
5. **Unlinked Google task** (not deleted, not assigned): import as a new local task unless `Completed` and its `CompletedAt` (fallback `Updated`) is older than `ImportCutoff`. **Unlinked eligible local task**: push as a new Google task.
6. **Linked pair**: per field compare each side with its own `Base`; `changedL = L != Base.L`, `changedG = G != Base.G`; neither → nothing; only G → write local; only L → write Google; both and different → local wins (D1, `Conflicts++`); both and equal → just update Base.
   After every write, Base is set from what the target side now reports: for a Google write, the returned `GTask`; for a local write, a re-read of the node (`WriteService.Get`) hashed/normalised the same way. Therefore the next cycle sees no difference (no write loop, no echo).

**Normalisation** (both sides, before any comparison, hash or Base update): titles: replace line breaks with a space, remove `<!--` and `-->`, replace `[[`/`]]` with `[`/`]`, trim; empty becomes "(untitled)". Notes: null becomes ""; `\r\n` and `\r` become `\n`; `TrimEnd()` the whole text (interior whitespace and inline checkbox lines are untouched); the hash is SHA-256 of the UTF-8 result. Dates: date part only (`Props.Date`) with no time-zone conversion; a datetime `due` compares equal to a Google date with the same date part, and a local datetime is never rewritten unless the date part differs.
Timestamps: Google `CompletedAt` (UTC RFC3339) is converted with `TimeZoneInfo.ConvertTime(value, clock.Zone)` and formatted with a new `Clock.Format(DateTimeOffset)` whose output is identical to `Clock.Stamp()` (`yyyy-MM-ddTHH:mm:sszzz`); `CreateTaskRequest.Completed` takes that string. Cutoff comparisons use `DateTimeOffset` instants, never strings. Google `Updated` is only compared with other Google `Updated` values.

**Field writes (local side)** go through `WriteService`, not `TaskService.Update/SetStatus` (which swallow `SaveStatus.ReadOnly` and cascade):
- title (only if not locked/read-only): `Rename` takes no base hash, so the check and the rename run together inside `WriteService.Exclusive(...)`: re-read the node, normalise its current title, and if it differs from `Base.Title.L` (the person retitled it meanwhile) skip the field (`Skipped++`, retried next cycle, the person's title wins); otherwise `WriteService.Rename(id, title, GoogleActor)` (renames the file, runs `AfterRename`/`SyncInline`, and rewrites `[[old title]]` links in other notes like any rename, D6). A `QuantosException` also means skip, do not update Base, `Skipped++`.
  The field writes below are the contents of the single coalesced `UpdateFields` call described in step 2, not separate calls.
- notes: `body: text` (the Google notes text; `ResolveLinks` may rewrite `[[Title]]`; `Base.Notes.L` is re-hashed from a re-read of the saved node). Note links are lossy by design (D8).
- due: `set:{due:"yyyy-MM-dd"}` or `remove:{due}` when Google cleared it.
- done: `set:{status:"done", completed:<Clock.Format(CompletedAt), else Clock.Stamp()>}`, or for reopen `set:{status:"todo"} remove:{completed}`; then `TaskService.SyncInline(id, done, null, GoogleActor)` for inline checkboxes. No `SetStatus`, so pulling completion never completes subtasks (each child syncs on its own); no `GenerateNext` (recurring tasks are excluded). A Google `needsAction` onto `doing`/`waiting` changes nothing.
- parent: `set:{parent:<plain task id>}` when Google gave a parent, or `remove:{parent}` when Google moved the task to top level (`Parent.G` became null), only if the target parent is a different, top-level (it has no parent), eligible, linked task in the same workspace (the engine's own check; `TaskService.ValidateParent` is not called, and cycles cannot arise from Google's one-level model plus the top-level rule). If a Google parent cannot be applied locally (the target is ineligible, nested, or not yet imported), `Base.Parent.G` is set to the Google value anyway so the change is not retried every cycle, and it is counted once in `Skipped`; it is applied later if the Google parent changes again.
- Every `UpdateFields` result is inspected: `Saved`/`Unchanged` = applied; `Conflict` (the file changed since the read, so the person edited it mid-cycle), `ReadOnly`, `Invalid`, `NotFound` = not applied, Base unchanged for those fields, `Skipped++`, retried next cycle. Because one call carries all fields and its hash is the freshest read, a task with several changed fields does not conflict with its own earlier write.
- New local tasks: `TaskService.Create` with `Extra = {gtask_id, gtask_list}` (the only keys `Extra` accepts), `Completed`, status, due, `Body = notes`, `Workspace` from the mapping, `Parent` resolved (parents created first within the same cycle; a pulled child whose parent is skipped is created without a parent).

**Google writes**: title (truncated 1,024), notes (D3), due, completed state, parent via `Insert(…, parent)` for new tasks or `Move` when it changes. Local `cancelled` and `done` both push `completed` (D2); local `todo/doing/waiting` push `needsAction`.
Parent sync: only a top-level task and its direct children participate (a local task nested two or more levels, or whose parent is not an eligible linked task, syncs flat on Google, and a Google-side parent change for it is ignored). Sibling order is not synced.
Push order within a cycle: first insert all unlinked top-level tasks (recording each returned gid in `Links` immediately), then children with `Insert(…, parent: <parent's gid>)`. If a child's parent is not linked by then (parent skipped, ineligible, or its insert failed) the child is inserted flat and recorded with `Base.Parent.L = null` and `Base.Parent.G = null` (Base records what was last synchronised, namely "no parent", not what is wanted), so in a later cycle the local parent id differs from `Base.Parent.L` and the ordinary only-L rule issues the `Move` once the parent is linked. A parent over the notes cap is still pushed (only its notes are skipped).
**Notes push transform (D8)**: before comparing or sending, local body text has `[[<id>|<text>]]` replaced by `<text>` and `[[<text>]]` by `<text>` (so raw ids never reach Google); `Base.Notes.L` hashes the transformed, normalised text. A pulled notes edit replaces the whole local body with the Google text, so wiki-links inside that body become plain text (documented limitation).
**Push insert crash safety**: before each `Insert`, an `Intents` record is saved; after `Insert` returns, in this order: write `gtask_id`/`gtask_list` to the task, then save the link, then drop the intent. At the start of a cycle, each leftover intent is resolved by looking in that list's unlinked Google tasks for exactly one whose normalised title and due equal the intent's and whose Google `Updated` is greater than the intent's `CursorAtIntent` (a Google value compared with a Google value, so device clock skew is irrelevant; the first-ever sync has no cursor, so there the title+due match alone applies): one match → link it; none → insert never happened, drop; several → link none, drop (a duplicate may result; logged at warning level).
**Durability**: `state.json` is saved (atomically) before every `Insert` (the Intent) and immediately after each `Insert` (the link), and after each delete; only other bookkeeping is batched (every 25 operations and at the end of a mapping).
The hint write's result is inspected like any `UpdateFields` result. Hint repair: at the start of each task's turn, any linked, eligible task whose node lacks `gtask_id`/`gtask_list` (a hint write that hit `Conflict`/`NotFound`, or a hint stripped by mistake) has them re-written (`derived: true`, fresh hash) before other work; a failure is retried next cycle. A crash after the local `gtask_id` write but before saving the link is repaired by the hint rule in step 4. **Pull crash safety**: the single `Create` carries the link keys, so a crash before the state save is repaired by the same hint rule.

**Deletes**
- Google → Quantos: a `Deleted` linked task is trashed with `WriteService.Trash(id, GoogleActor)` only if all of these hold: the task is not locked/read-only; it has no non-trashed local subtasks (`Trash` cascades to subtasks and would destroy local-only children); and it has no unsynced local change (no field with `L != Base.L`, so a Google delete never silently discards a local edit). Deleted children are processed before parents. Otherwise the link is dropped, the `gtask_id`/`gtask_list` hints are removed, the task is kept (it will be pushed again as a new Google task) and `Skipped++`/`Conflicts++` as appropriate. Unlinked deleted Google tasks are ignored.
- Quantos → Google: a linked task is "locally deleted" only if, evaluated inside `WriteService.Exclusive(...)` (the gate `Reconciler.Run` uses, so a reconcile cannot be half-applied), the vault root matches the pin, `WriteService.Get(id)` is null **and** its id is in the once-per-cycle trash id set (step 2). A task that is missing without a trash entry is "unknown": skipped, link kept, logged, and the link's `Missing` counter is incremented; after 3 consecutive cycles in which it is still missing with no trash entry (an explicit permanent delete, which needs the person's approval) it is treated as locally deleted. The counter resets when the task reappears.
  Order and shared-gid check: duplicate-hint resolution (step 4) always runs before the delete pass in a cycle. Before sending any Quantos → Google `Delete`, if a different live local task (`Get` non-null and not in the trash set) in a mapped list carries `gtask_id` equal to the gid (the owner of a deduplicated copy, or a copy the person restored), the link is re-keyed to that task and **no Delete is sent**.
  Keep-if-edited (the mirror of the Google → Quantos rule): before sending `Delete`, the engine calls `Get(listId, gid)`; if the Google task is absent it is simply unlinked; if any Google field differs from `Base.G` (the Google side has an unsynced edit) the delete is **not** sent: the link is dropped, that mapping's cursor is reset, and the task is re-imported as a new local task (`Conflicts++`). Otherwise `Delete(listId, gid)`; 404/410 count as success (Google already removed children when it removed their parent).
  Link lifecycle: after any delete completes in either direction (including the engine's own `Trash` for `toQuantos` and the `Delete` for `toGoogle`) the link is removed from `Links` in the same state save, so the next cycle cannot re-detect it and double-count against the guard.
- Google "Clear completed" produces `Hidden` completed tasks, which are listed (`showHidden=true`) and are not deletions.
- Guard (scope: one `Run`, all mappings together; `Links.Count` is the total across all mappings): if the deletions of this run (either direction) **plus any entries already held** would exceed `max(10, 25% of Links.Count)` — "exceed" means strictly greater — none of them run. While any entries are held, newly detected deletions join the held set instead of executing, until Apply or Cancel; they are stored in `PendingDeletes` and Settings shows them. `POST /deletes {apply}` runs them, **re-running every check at apply time for each entry** (lock/read-only, local subtasks, keep-if-edited on both sides, the `Exclusive` + trash-set test, and `Get`): an entry that no longer passes is dropped and counted in `Skipped`, never forced; `{cancel}` drops them and keeps both sides: for a task the person trashed locally (`toGoogle`), the Google task is left alone, its link is removed and that mapping's cursor is reset so the next cycle does a full fetch and re-imports it as a new local task (deterministic, not cursor-dependent); for a task deleted on Google (`toQuantos`), the local task is kept, its link and `gtask_id`/`gtask_list` hints are removed (so the hint rule cannot relink it to the deleted gid), and it is pushed again as a new Google task.
- Restore from Quantos trash: see step 4 (stale hint removed, task pushed as new).

## Timing, hosting and lifecycle
- `GoogleTasksCoordinator : BackgroundService` mirrors `SyncCoordinator`: a `SemaphoreSlim` gate (single flight), `Open` throws "Open the vault this was set up for" if `Vault.PathEquals` fails, cancellation of an in-flight run and of a pending OAuth flow on `PUT /settings` mappings change, `DELETE /`, or shutdown.
- Loop: every `IntervalSeconds`, or sooner on `Kick()`. A `ChangeHub` handler (`host.Require().Changes.Changed`, re-subscribed whenever `host.Session` changes, checked each tick) restarts a 5 s timer on events of kind Created, Updated, Moved, Trashed, Restored, Deleted, Archived, Unarchived, Reindexed whose `Origin` does **not** start with `System:` (the engine's own writes use `System:google-tasks`, and their side effects — link rewrites by `Rename`, inline-checkbox updates — publish with other `System:…` origins; ignoring the whole `System:` kind means the engine never kicks itself). The timer fires `Kick()`. Changes that arrive with a `System:` origin from elsewhere (shared-vault sync, reminders) are picked up by the next interval tick instead. An idle cycle makes zero writes.
- Back-off is global (one failure counter and one `nextAttempt` for the whole coordinator), in memory, reset on success and on restart: transport errors, timeouts, 5xx, 429 and 403 `rateLimitExceeded` give delay = interval × min(2ⁿ, 8) for n consecutive failures, using `Retry-After` when present; `nextAttempt` is shown in the status. Auth failures do not retry.
  Per-mapping conditions are not failures and do not back off or block other mappings: a missing list (`ListTasks` for that list returns 404 → that mapping `Paused` "List missing: <title>"; no per-cycle `ListTaskLists` call is made, so quota is unchanged), a missing workspace, or an unconfirmed mapping. A 404/410 from `Get`/`Patch`/`Move` is task-level (the Vanished-gids rule), never list-level.
- Mapping change: removing a mapping, or replacing its workspace or list, drops that (workspace, list) pair's `Links`, `Cursors` and `PendingDeletes` from state and cancels any run in progress. Local hints and Google tasks are left as they are; stale hints are then handled by the hint list rule in step 3 (so a workspace moved to a new list pushes its tasks into the new list after the new mapping is previewed and confirmed). Re-adding the old pair starts with no links and relinks through the hints.
- Quota: 50,000 requests/day; one `ListTasks` per mapping per cycle (~720/day/list at 120 s). First sync sends requests sequentially at ≤ 5/s and reports `progress`; it is resumable because every item is idempotent and the state is saved as described under Durability (per insert and delete; other bookkeeping every 25 operations and at the end).
- Two devices (D5): enabling it on a second device links existing tasks by their `gtask_id` hints. While a hint is still travelling through shared-vault sync, the second device may import a copy; the duplicate-hint rule in "Link resolution" then trashes the redundant copy (identical content) or strips the hints from a diverged one. **Simultaneous first syncs on two devices are unsupported**; the user guide recommends syncing from one device.
- Independent of the shared-vault `SyncEngine`: tasks that arrive by vault sync are just local changes/new tasks to this engine.

## UX flow
Settings › Google Tasks (its own section, after Shared vault; same layout on phone; verify no horizontal overflow at 390px):
1. Setup text with the Cloud Console steps and links; fields Client ID and Client secret (password field), Save.
2. Connect button → `POST /connect` → native clients `bridge.send open-external`; ordinary browsers show a "Continue to Google" link. While `flow = "waiting"` the page polls `GET /` every 2 s for up to 10 minutes, then shows "Timed out — try Connect again".
3. Lists: one row per mapping: workspace select, Google list select (from `GET /lists`) with "New list…" (`POST /lists`); Add/Remove row; inline validation errors from `PUT /settings`.
4. Each mapping row has a Preview button (`POST /preview {workspace}`) → counts shown in that row (create in Google / import to Quantos / already linked / left out, for tasks closed in the last 30 days or still open) → "Confirm and sync this list" (`POST /confirm` then `/sync`). Unconfirmed rows show "Review the preview first".
5. Status line (`aria-live="polite"`): "Last synced 14:02 · 3 pushed · 1 imported · 2 skipped"; Sync now; interval select (1, 2, 5, 15 min); Reconnect button on `NeedsReconnect`; Disconnect.
6. Pending deletions: a table listing each task and direction with Apply and Cancel buttons; focus moves to the table heading when it appears; both buttons are keyboard operable.
Store API in `lib/googleTasks.svelte.ts`: `load()`, `saveSettings()`, `connect()`, `lists()`, `createList()`, `preview()`, `confirm()`, `syncNow()`, `resolveDeletes()`, `disconnect()`, plus pure helpers `validateMappings(mappings)` (invalid: empty workspace or list, duplicate workspace, duplicate list) and `statusLabel(status)`.

## Project-specific concerns
- Every vault change goes through `WriteService` (only via the calls above). Derived state (`state.json`) lives in `client-data` and is rebuildable (hints).
- Local and private by default: opt-in; only `accounts.google.com`, `oauth2.googleapis.com`, `tasks.googleapis.com` are contacted; documented in `SECURITY-MODEL.md`.
- Secrets are device-owned and never in the vault, git, logs, exception messages or API responses. Logging: log gid and local task id only, never titles/notes, tokens, `code` or `state`.
- User-only API; agents, plugins and automations are blocked both by the endpoint filter and by the `RequestSecurity` prefix list.
- Accessible: labelled controls, keyboard path for every action, axe scan clean; plain British-leaning text; user guide updated.

## Failure modes
| Failure | What happens / what the user sees |
|---|---|
| Offline / DNS | "Can't reach Google, will retry at <time>"; local edits kept; back-off |
| `invalid_grant`, revoked, 6 months unused, unsealable secret | `NeedsReconnect`, sync stops, Reconnect button; no task data touched |
| 403 API not enabled | "Turn on the Google Tasks API for your project" with a link |
| 403/429 quota | Back off per `Retry-After`; next attempt time shown |
| List deleted on Google | That mapping `Paused` ("List missing"); its tasks stay local, links kept |
| Callback with a wrong state or no pending flow | HTTP 400 static page; a pending flow is kept |
| Callback after the flow expired | HTTP 400 static page; flow discarded |
| Browser closed mid-consent | Flow expires in 10 min; click Connect again |
| App restarted mid-consent | Flow lost; click Connect again |
| Corrupt/lost `state.json` | Rebuild from hints; local-wins, no deletes that cycle |
| Corrupt `google-tasks.json` | Treated as Off |
| Different vault open | `Paused`: "Open the vault this was set up for" |
| Locked/read-only task on pull | Field skipped, counted in Skipped, retried next cycle |
| Person edits a task while a cycle runs | `Conflict` from the base-hash check; field skipped, retried next cycle; their edit survives |
| Consent screen without the Tasks box ticked | Nothing stored; "Tick the Google Tasks box on the consent screen and try again" |
| Google call times out (30 s) | "Google did not respond in time"; back-off; gate released |
| Hint for a list this device does not map | Task left alone and counted in Skipped |
| Notes over 8,000 characters | Notes skipped for that task, other fields sync |
| Crash mid-insert / mid-import | Repaired by Intents and hint rules; at worst one logged duplicate |
| Missing task without a trash entry | Treated as unknown, not as a delete |
| Too many deletions in a cycle | Paused for the person to Apply or Cancel |

## Verification criteria
Core xUnit (`tests/Quantos.Tests/GoogleTasksTests.cs`) with a fake `IGoogleTasksApi` and a real `WriteService` over a temp vault:
- Mapper: title normalisation, due date-part with datetime and around a DST change, status matrix (including `cancelled`), notes cap, parent depth rules.
- Merge: only-L, only-G, both-changed (local wins, `Conflicts` counted), both-equal; steady state: second cycle makes zero local writes and zero API writes; echo suppression after a push.
- Pull writes: a locked task is skipped and Base unchanged; completion does not cascade to local subtasks; titles with `[[`, `<!--` and newlines normalise without a loop; ResolveLinks-rewritten body does not loop.
- Crash injection after each step of insert, link write, state save, and import `Create`: next cycle never duplicates, or logs the single allowed duplicate.
- Deletes: leaf-first, parent with local subtasks kept, 404/410 success, missing-without-trash is unknown, guard floor (`max(10, 25%)`) with Apply and Cancel outcomes, restore from trash, "Clear completed" is not a delete.
- Eligibility: archive/recurrence/workspace move suspends, resumes when eligible again; assigned tasks skipped; import cutoff never pulls old completed tasks later.
- Paging (more than 100 tasks), cursor not advanced on failure/cancel, first-sync preview counts; `Preview` makes zero local writes, zero state writes and zero Google mutations (fake API records calls).
- Locks and hashes: a locked and a `ReadOnly` task are never renamed, edited, completed or trashed by the engine but can be pushed; a body edited between snapshot and write yields `SaveStatus.Conflict`, the field is skipped and retried next cycle, and the person's edit survives.
- Hints: a foreign-list hint is untouched and the task skipped; a restored-from-trash task whose gid is `Deleted` or 404 on `Get` has its hints stripped and is pushed as new; cancelled pending deletes in both directions (hints stripped for `toQuantos`, cursor reset and re-import for `toGoogle`); Google delete of a locally edited task keeps the task.
- Two-device race: two engines over one vault with a delayed hint: the older task survives on both devices, the redundant newer copy is trashed (identical content) or hint-stripped (diverged, locked, or with subtasks), the Google task is never deleted by either device, and the owner is the same on both devices (device-independent rule).
- Multi-field writes: a task whose title, notes, due, done state and parent all changed on Google in one cycle is updated in that cycle with no `Conflict` and no second-cycle retry; a person's edit made between read and write still produces `Conflict` and survives.
- Locked tasks: a locked task is pushed and its hints written (`derived: true`), a Google edit to it is skipped, and after deleting `state.json` the link is rebuilt from the hints; a `ReadOnly` task is never pushed.
- Vanished gids: `Patch`/`Move`/`Get` 404 and a full fetch missing a linked gid both take the Google-deleted path; a task trashed by the engine has its link removed in the same save (no second delete); a permanently removed task is treated as deleted after 3 missing cycles; a Google edit prevents the Quantos → Google delete (task re-imported).
- Mapping change: changing a workspace's list, removing a mapping, and re-adding it behave as specified (links/cursors/pending deletes dropped, stale hints cleared, tasks pushed to the new list, old Google tasks untouched, foreign-workspace hints untouched).
- Push ordering: a new parent and child in one cycle are inserted parent first; a child whose parent insert fails is inserted flat and moved later.
- Callback: a wrong-state request returns 400 and the pending flow still completes afterwards; an expired flow is discarded.
- Trash scan: `TrashStore.List()` is called once per cycle regardless of the number of missing tasks (counted through a test double).
- Preview counts: exact `CreateInGoogle`, `ImportToQuantos`, `Link`, `Excluded` for a fixture covering hints, recurring, archived, ReadOnly, assigned and pre-cutoff completed tasks.
- `Extra` accepts only `gtask_*` keys (others throw); notes push transform removes ids from `[[id|text]]`.
- Guard arithmetic: with 20 links, 10 deletions run and 11 are held (floor branch); with 100 links, 25 run and 26 are held (percentage branch); with entries already held, one new deletion joins the held set instead of running; scope is the whole `Run` across mappings.
- Cursor reset wins: a keep-if-edited or Cancel reset in a pass is not overwritten by that pass's cursor advance, and the task returns on the next cycle.
- Parent: flat insert then `Move` once the parent is linked; Google moving a child to top level removes the local `parent`; an inapplicable Google parent is counted once, not every cycle.
- Shared gid: when device A trashes a deduplicated copy and device B (which linked that copy) sees the trash, B re-keys its link to the owner and does not delete the Google task; a restored copy likewise.
- Hint repair: a hint write that hits `Conflict` is re-written next cycle; after `state.json` is deleted the task relinks instead of being pushed again.
- Pending deletes: a Google-side deletion seen once survives the cursor advancing and an app restart until Apply/Cancel; Apply re-checks lock, subtasks and both keep-if-edited rules and drops an entry whose task was edited meanwhile; entries merge by task id (not replaced).
- Preview memory: preview for (W, list A), change the mapping to list B, then `/confirm` → 409; Disconnect and mapping removal clear it.
- Title guard: a person retitling a task between the engine's read and its `Rename` keeps their title (skipped, retried).
- Intent recovery with a device clock skewed by ±10 minutes still links the already-inserted task (no duplicate); first-sync recovery without a cursor.
- Truncation: a 1,500-character local title pushes 1,024 characters and produces no change on the next cycle; a Google title edit replaces it.
- Status matrix: `cancelled`/`done` push `completed`; Google reopen turns `cancelled` and `done` into `todo`; `doing`/`waiting` are untouched by `needsAction`.
- Initial `Base`: hint relink, second-device attach and state rebuild seed Base, local wins on differing fields, and issue no deletes in that cycle.

## Draft 7 clarifications (authoritative; they refine the sections above)
After the draft-6 passes (readiness: ready; critic: 7 gaps) the owner chose to fold these in and proceed to implementation.
1. **Error classes.** From the Google error body's first `errors[].reason`: `rateLimitExceeded`, `userRateLimitExceeded`, `quotaExceeded`, HTTP 429 and 5xx/timeouts → global back-off. `insufficientPermissions` (or any 403 on a list-level call such as `ListTasks`/`ListTaskLists`) → `NeedsReconnect`. `accessNotConfigured` / `SERVICE_DISABLED` → "API not enabled" message (global stop until Sync now). 401 after one refresh → `NeedsReconnect`. **Any other 4xx from a single-task call** (`Insert`, `Patch`, `Move`, `Delete`, `Get`; for example 400 invalid parent, a 403 on an assigned task, a rejected title) is task-level: that task is skipped this cycle (`Skipped++`), a per-task error is kept in memory and shown as "N tasks couldn't sync", the mapping does not fail, the cursor still advances (the task is re-evaluated each cycle from Base, not from the cursor), and no global back-off applies.
2. **Parent move ordering.** Only leaf tasks (no non-trashed local children) are ever given a Google parent; a task that has local children stays top-level on Google. Within a cycle all `Move`s to top level run before moves under a parent.
3. **Pristine test for trashing.** A local task is trashed by the engine (redundant duplicate copy, or a Google-side delete) only if it is *pristine*: its frontmatter has no keys outside `{id, type, title, created, modified, schema, workspace, tz, status, completed, due, parent, gtask_id, gtask_list}`, it has no tags, and it also passes the lock, `ReadOnly`, no-subtask and (for Google-side deletes) keep-if-edited checks. Otherwise it is kept: for a duplicate only its hints are removed; for a Google-side delete the link and hints are dropped and it is pushed again as new (`Skipped++`).
4. **Suspended links never cause Google deletes.** If a suspended task (archived, recurring/series, moved to another workspace) is later trashed, its link is dropped silently and nothing is sent to Google. The Quantos → Google delete pass considers only non-suspended links.
5. **Engine contract.** `interface IGoogleTasksStateStore { GoogleTasksState Load(); void Save(GoogleTasksState state); }` (file-backed in production with `AtomicFile`, so tests can fail or interrupt a `Save` for crash injection; the whole state object is saved). `GoogleTasksSyncEngine(WriteService writes, TaskService tasks, Clock clock, IGoogleTasksStateStore state, IGoogleTasksApi api)` exposes `Run(IReadOnlyList<GoogleListMapping> confirmedMappings, CancellationToken ct)` (the coordinator passes only mappings with `Confirmed = true`; each mapping's `ImportCutoff` comes from it), `Preview(GoogleListMapping mapping, ct)`, `ApplyPendingDeletes(ct)`, `CancelPendingDeletes(ct)` (applies the Cancel rules, including cursor resets), and `ResetMapping(string workspace, string listId)` which drops that pair's `Links`, `Cursors`, `Intents` and `PendingDeletes` (the coordinator calls it on a mapping change or removal; Disconnect deletes the state file).
6. **Intent recovery** runs inside step 1, after the pages are fetched and before link resolution (step 4). `Intents[].TitleNorm` is the normalised title **truncated to 1,024 characters** (what Google returns), so long titles match on recovery. `ResetMapping` also drops `Intents`.
7. **Notes sync eligibility.** Supported link forms in a body: `[[id|text]]` → `text`, `[[Title]]` → `Title`, `[[Title|alias]]` → `alias`. If a body contains an embed (`![[`) or any other bracket form (containing `#` or `^`, or not matching the supported forms), notes are not synced for that task in either direction (like the 8,000-character cap, D3; `Skipped++`).
8. **Smaller points.** Token revoke is `POST https://oauth2.googleapis.com/revoke` with an `application/x-www-form-urlencoded` body (`token=…`), never in the URL. `ListTaskLists` and `GET /lists` page with `maxResults=100` and follow `nextPageToken`. `Program.cs` registers (as singletons) `GoogleOAuth` (with its own `HttpClient`), `GoogleTasksSettingsStore`, `IGoogleTasksApiFactory`, `GoogleTasksCoordinator` (also as the hosted service). A change of `clientId` or `clientSecret` also cancels any pending OAuth flow. The delete-guard test is two cases: with 20 links, 10 deletions all run; with 20 links, 11 deletions are all held (none runs); likewise 25 run / 26 held with 100 links.
9. **Status numbers.** `counts.pushed/pulled/skipped` and the status-line text show the last completed cycle's report (reset every cycle); `counts.linked` and `pendingDeletes` are current. `POST /sync` while a run is in flight waits for the gate (as `SyncCoordinator.SyncNow` does) and then runs its own cycle and returns that report; the timer loop and `/sync` never run concurrently.
10. **Unresolved parents.** For a Google child whose parent gid was not in the fetched pages: resolve it through `Links` (gid → task id); if there is no link, call `Get` for the parent once; if the parent is absent or `Deleted`, import the child flat. A non-rate-limit 403 reason not listed above on a list-level call is treated as `NeedsReconnect`.

## Behaviour added in review (after draft 7)
- A task that becomes eligible again after being suspended is resumed by asking Google for its current state (`Get`), because the incremental fetch has moved past any edit made meanwhile. It stays marked suspended until the resume (merge) succeeded and no pull was held back, so a failure or a locked task is retried.
- Consequence, accepted: a task whose resume has not yet succeeded still counts as suspended, so trashing it in Quantos drops the link and leaves its Google task alone (the "suspended tasks never cause a Google delete" rule). That Google task comes back as a new task if it is edited in Google later.
- A held-back Google change (locked or read-only task, the person editing it) keeps the sync cursor before that change for up to 24 hours; after that it is let go and counted as skipped.
